# Project Overview — 研究の全体像(理解用)

> 目的: 「パープルチームでオープンソースを使って計測する」という抽象的な認識を、具体的な絵にするための参考資料(Claude 作成・理解用)。
> 提案書の本文はこれを参照しながら自分の言葉で書く。生成 AI を使ったことは Acknowledgements に記録する。

## この研究を具体的な一文で
決められたいくつかの攻撃的な振る舞いを、隔離ラボの中で順番に起こしてみて、
オープンソースの検知が **それぞれを気づけたか / 見逃したか** を記録し、網羅と盲点を数える。
= 攻撃を研究するのではなく、検知の健康診断をする研究。

## ラボの 5 つの部品(役割で理解する)
| 部品 | 役割 |
|---|---|
| 1. 標的(被害 VM) | 測定対象のふつうの PC。ここで振る舞いを起こす |
| 2. 記録係(ログ収集) | 標的で起きたことを記録する(Sysmon など) |
| 3. 検知エンジン(SIEM) | 記録を見て「これは怪しい」とアラートを出す ← 評価する本体 |
| 4. 実行係(テストランナー) | 公開済みのテスト集(Atomic Red Team)を順番に起こす |
| 5. 結果係(集計・可視化) | 検知できた / 見逃した を表とヒートマップにする |

## 研究の心臓 = 繰り返す測定ループ
振る舞いを 1 つ起こす → ログが出る → 検知が鳴るか見る → 「○検知 / ×盲点」を記録 → 次へ。
これを決めた数だけ回すと、網羅の地図ができる。この地図が論文の結果。

## 測るもの(数字になるもの)
- 検知できた割合(網羅)
- 見逃した振る舞い(盲点)
- 戦術カテゴリ別に、強い所・弱い所

## 最終的に出すもの(成果物の形)
- ATT&CK 上に塗った網羅ヒートマップ(ATT&CK Navigator)
- 盲点リスト(どのカテゴリが弱いか)
- 検知の判定ログ(再現用)

## 「曖昧」の正体 = まだ決めていない 5 つ
ここを埋めると一気に具体になる。
1. 範囲: いくつの振る舞いを、どの戦術カテゴリから選ぶか(例: 5〜10 個、2〜3 カテゴリ)
2. 検知スタック: Wazuh か Sentinel か(+ Sigma ルールをどこから持ってくるか)
3. 「検知できた」の定義: アラートが 1 つでも出れば OK か、正しい手法に紐づく必要があるか
4. ログ設定: Sysmon の設定をどれに固定するか(設定で結果が変わるため)
5. 出し方: 何を表・図にするか(ヒートマップ + 盲点リスト)

## 具体的な RQ の例(測定レベルまで下ろす)
- このオープンソース検知スタックは、選んだ N 個の振る舞いのうち何個を検知できるか?
- どの戦術カテゴリに盲点が集中するか?
- (任意)検知できた振る舞いに小さな変化を加えると、検知は保たれるか?
